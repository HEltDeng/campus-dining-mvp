# 禾饭 · 校园食堂到寝室

一个在本机运行的校园外卖 MVP。学生、商家、平台管理与配送角色使用同一套 FastAPI API 和持久化 SQLite 数据库。所有支付、退款和配送均为明确标示的演示流程，不连接银行、支付渠道、美团业务接口、短信或地图服务。

正式源码目录：`D:\Codex\01_App-应用开发\008_CampusDining-校园食堂配送`。

研究材料继续保留于 `D:\Codex\07_Research-研究实验\008_Meituan-美团安卓逆向研究`。本项目依据业务需求独立实现，没有复制美团反编译代码、私有接口、界面素材或账号数据。

## 启动

在项目根目录运行：

```powershell
.\scripts\start.ps1
```

打开 **http://127.0.0.1:8876/**。初次运行会在本项目内建立 `.venv` 并安装锁定依赖；本机当前已经配置完成。窗口保持运行，`Ctrl+C` 停止服务。默认仅监听本机，数据存于 `runtime/campus-demo.sqlite3`，停止和重启不会清空。

直接启动等价命令：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8876 --no-access-log
```

不提供自动清空数据库按钮或启动时重置。依赖见 `requirements.lock.txt`，基础依赖见 `requirements.txt`。本机验证 Python 3.11；网页不需要 Node 构建。Node 仅用于开发时语法检查。

## 一次完整体验

1. `student` 选择档口、菜品规格、口味、加料和数量，加入餐袋。
2. 填写明确标示的演示楼栋、楼层和寝室号。A 栋支持送到寝室；B 栋需明确确认楼下交付；C 栋未开放。它们不是学校真实楼栋规则。
3. 点击“核价并确认”，查看服务器计算的商品金额、餐盒费、配送费。创建本地测试订单，再点击“模拟支付 · 不扣款”。
4. 切换 `merchant` 接单并备餐，点击“出餐完成”；或在未接单时填写原因拒单并模拟退款。
5. 可以切换 `admin` 指派配送员，再用被指派的 `rider` 接受；也可以让 `rider` / `rider_b` 直接从待接队列抢单。同一任务只能由一人领取。
6. 配送员确认取餐，在订单约定的交付点确认送达。学生最后确认收餐。
7. 学生未被商家接单前可取消；备餐开始后可申请售后。管理员处理全额模拟退款。配送途中退款不会伪造送达，也不会把熟食重新计入可售库存。

商家入驻：使用 `applicant` 提交所属食堂、档口名和经营描述；切换 `admin` 或对应学校运营审核；审核通过后刷新申请账号，自动获得本档口商家角色，可创建菜单。

## 已实现的业务保护

- 金额用整数分保存，由服务器重新核算；客户端不能传入一个总价作为订单金额。
- 报价有效期 3 分钟；商品价格、内容或配送规则变化要求重新报价。库存变化单独重验，订单保存商品和地址快照。
- 一个订单仅属于一个学校、校区、档口和地址。规格、加料校验归属和必选/最多数量。
- SQLite WAL、`BEGIN IMMEDIATE` 事务、条件库存扣减；库存与订单、明细、事件在同一事务写入。库存编辑也使用版本，不能覆盖刚发生的预占。
- 下单幂等键按账号唯一，同键不同报价拒绝；同一报价只能生成一个订单。模拟支付按订单和事件去重，金额必须一致。
- 学生仅可访问本人订单；商家仅可访问自己档口；学校运营和配送员仅限授权学校/校区；所有权限由后端校验。
- 配送候选和派单邀约不暴露寝室号；接单后按需展示，送达、回收或转派后撤销详细地址访问。
- 状态操作带版本，拒绝重复抢单、非法跳转、未取餐直接送达、已取餐回收等操作。
- 拒单/未接单取消释放库存且最多一次；开始制作后的退款不恢复库存。退款金额仅全额，账本最多一笔。
- 每 10 秒扫描数据库期限，恢复未支付超时订单和过期派单邀约；启动和相关请求也会恢复。截止时间保存在数据库中，重启不丢失。未支付超时为 15 分钟，派单邀约为 120 秒，均为演示默认值。
- 同源写入检查、本机 Host 限制、参数额外字段拒绝、数据库外键、密码 PBKDF2 和会话令牌哈希。演示账号公开，不能直接作为生产认证方案。

## 首期裁剪和生产接入缺口

本次是可操作的本地 MVP，不是正式上线系统。学校首站采用四川农业大学雅安校区场景草案；具体食堂、菜单、宿舍和上楼权限全部为演示配置。第二学校用于真实代码层的数据隔离验证。

首期支持单档口订单、全额退款、手动派单和抢单。新建商品先创建一个规格，预置商品提供多规格与加料；更完整的规格/选项编辑、营业时段、骑手容量、批量合单、部分退款、复杂优惠和自动结算未实现。学校管理支持草案和启停，但新学校真实食堂、账号、校区与范围的完整自助开通仍待扩展；拒绝后的商家申请暂未提供重提界面。

支付、退款使用强制 `LOCAL_DEMO` 适配逻辑；登录为演示账号密码，不发送短信；地址由演示楼栋选择，不调用地图定位；配送为本地任务，不发送到外部配送平台。真实支付应增加商户资质、服务端签名验签、交易查询、迟到回调补偿、真实退款对账和结算；不能把当前模拟支付入口接到生产。

生产还缺校方/食堂实际准入与楼栋规则、真实商家与菜品数据、身份认证与账号管理、生产密钥管理、HTTPS、限流、监控、备份恢复、数据保留策略、容量压测及运营验收。没有进行 GitHub 推送、生产部署或应用商店发布。本轮不修改其他产品或生产服务。
